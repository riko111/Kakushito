# PDF座標系・画面座標系変換仕様

## 1. 目的

「かくしーと」では、PDF上に描画するマーカー等の位置情報を、端末や画面サイズ、ズーム倍率などに依存しない形で保存する。

そのため、**PDF座標を唯一の正規座標系（Canonical Coordinate System）として扱い、画面への表示時にのみ画面座標へ変換する**。

これにより、同じPDFに対して以下の環境でもマーカー位置を正確に維持できる。

* スマートフォン
* タブレット
* PC
* Web
* 画面サイズの違い
* 画面回転
* PDFのズーム倍率変更
* PDF表示領域の変更

---

## 2. 基本方針

### 2.1 正規座標系

アプリ内部で保存する座標は、原則として**PDF座標系**とする。

```text
PDF座標
  ↓
保存データ
  ↓
表示時に画面座標へ変換
```

画面上で取得した座標をそのまま保存してはならない。

---

## 3. PDF座標系

PDFのページ座標は以下を基本とする。

```text
原点：ページ左下
X軸：右方向が正
Y軸：上方向が正
単位：pt（point）
```

概念図：

```text
        Y+
        ↑
        │
        │
        │
        └────────→ X+
       (0, 0)
```

例えば、ページサイズが `595 × 842 pt` の場合、

```text
左下     : (0, 0)
右下     : (595, 0)
左上     : (0, 842)
右上     : (595, 842)
```

---

## 4. 画面座標系

画面座標は、使用するUIフレームワークの座標系に従う。

基本的には以下を想定する。

```text
原点：画面左上
X軸：右方向が正
Y軸：下方向が正
単位：logical pixel
```

概念図：

```text
(0, 0) ─────────→ X+
  │
  │
  │
  ↓
  Y+
```

PDF座標とはY軸の向きが逆になる点に注意する。

---

# 5. 座標変換

## 5.1 PDF座標 → 画面座標

PDFを画面上に表示する際は、

```text
PDF座標
    ↓
拡大・縮小
    ↓
配置位置へのオフセット
    ↓
画面座標
```

という変換を行う。

基本的な変換式は以下とする。

```text
screenX = offsetX + pdfX × scale
screenY = offsetY + (pdfHeight - pdfY) × scale
```

ここで、

* `pdfX`：PDF上のX座標
* `pdfY`：PDF上のY座標
* `pdfWidth`：PDFページの幅
* `pdfHeight`：PDFページの高さ
* `scale`：表示倍率
* `offsetX`：画面上でのPDF表示領域のX方向オフセット
* `offsetY`：画面上でのPDF表示領域のY方向オフセット

とする。

---

## 5.2 画面座標 → PDF座標

ユーザー操作によって画面座標が取得された場合は、PDF座標へ逆変換する。

```text
pdfX = (screenX - offsetX) / scale

pdfY = pdfHeight - (screenY - offsetY) / scale
```

ユーザーがマーカーを引いた場合は、この逆変換を行った後のPDF座標を保存する。

---

# 6. 表示倍率（Scale）

PDFページを画面に表示する際、PDFの縦横比を維持する。

例えば、

```text
PDFサイズ
pdfWidth  = 595 pt
pdfHeight = 842 pt

表示領域
viewWidth  = 400 px
viewHeight = 600 px
```

の場合、

```text
scaleX = viewWidth / pdfWidth
scaleY = viewHeight / pdfHeight

scale = min(scaleX, scaleY)
```

として、PDFページ全体が表示領域に収まる倍率を求める。

---

# 7. 表示位置（Offset）

PDFページを画面中央に配置する場合、PDFの表示サイズを

```text
displayWidth  = pdfWidth × scale
displayHeight = pdfHeight × scale
```

として、

```text
offsetX = (viewWidth  - displayWidth)  / 2
offsetY = (viewHeight - displayHeight) / 2
```

とする。

ただし、スクロールやパン操作を行う場合は、これらにスクロール位置・パン位置を反映する。

---

# 8. マーカーの保存

マーカーは**PDF座標系で保存する**。

例えば、横線のマーカーの場合、

```text
Marker {
    page: 3,
    startX: 120.5,
    startY: 450.2,
    endX: 380.1,
    endY: 450.2
}
```

のように保存する。

### 保存してはいけないデータ

以下のような画面依存の座標を永続化してはならない。

```text
screenX
screenY
offsetX
offsetY
scale
```

これらは表示状態であり、必要に応じてその都度計算する。

---

# 9. マーカー描画処理

マーカーを描画するときは、保存されているPDF座標を画面座標へ変換する。

```text
保存済みMarker
      │
      │ PDF座標
      ↓
PDF → Screen変換
      │
      │ 画面座標
      ↓
Canvas / Overlay
      ↓
画面にマーカーを描画
```

例えば、

```text
Marker:
    start = (120, 450)
    end   = (380, 450)
```

の場合、

```text
startScreen = pdfToScreen(120, 450)
endScreen   = pdfToScreen(380, 450)
```

として描画する。

---

# 10. マーカー入力処理

ユーザーが画面上でマーカーを引いた場合は、入力された画面座標をPDF座標へ変換して保存する。

```text
ユーザー操作
      ↓
画面座標を取得
      ↓
Screen → PDF変換
      ↓
PDF座標のマーカーを生成
      ↓
保存
```

例えば、

```text
ユーザー操作：

画面
(100, 250) → (300, 250)

        ↓ 逆変換

PDF
(125, 400) → (375, 400)

        ↓

PDF座標として保存
```

---

# 11. ズームへの対応

ズーム倍率は保存データに影響させない。

例えば、同じマーカーがPDF座標上で、

```text
(200, 300)
```

に存在する場合、

```text
scale = 1.0
```

でも、

```text
scale = 2.0
```

でも、保存値は常に、

```text
(200, 300)
```

とする。

表示時に現在の倍率を使用して画面座標を計算する。

```text
PDF座標
(200, 300)
    ↓
現在のscale
    ↓
画面座標
```

これにより、ズームしてもマーカーがPDF上の同じ位置に追従する。

---

# 12. スクロール・パンへの対応

スクロールやパンによってPDFの表示位置が変化しても、保存されているPDF座標は変更しない。

```text
PDF座標
   ↓
scale
   ↓
PDF表示位置
   ↓
scroll / pan
   ↓
画面座標
```

スクロール位置やパン位置は**表示状態として管理する**。

---

# 13. 画面回転への対応

画面回転によって、

```text
viewWidth
viewHeight
```

が変化しても、PDF座標で保存されたマーカーは変更しない。

再レイアウト後に、

```text
PDF座標
    ↓
新しい表示倍率
    ↓
新しい表示位置
    ↓
画面座標
```

として再計算する。

---

# 14. ページごとの座標系

PDFはページごとにサイズが異なる可能性があるため、座標変換には**対象ページのサイズ**を使用する。

例えば、

```text
Page 1
595 × 842 pt

Page 2
842 × 595 pt

Page 3
612 × 792 pt
```

の場合、それぞれのページについて独立して座標変換を行う。

マーカーには必ずページ番号を保持する。

```text
Marker {
    page: 3,
    startX: ...,
    startY: ...,
    endX: ...,
    endY: ...
}
```

---

# 15. 将来的な実装方針

単純なPDF表示だけであれば、

```text
scale + offset
```

による変換で実装できる。

ただし、以下への対応を考慮し、内部的には**座標変換行列（Transformation Matrix）として扱える設計**を推奨する。

* PDFページの回転
* ページごとの異なるサイズ
* CropBox / MediaBox
* ズーム
* パン・スクロール
* 画面回転
* 将来的な表示変換
* PDFレンダリングライブラリごとの座標系差異

概念的には、

```text
PDF座標
   ↓
PDFページ変換
   ↓
Viewport座標
   ↓
Zoom / Pan
   ↓
Screen座標
```

という変換パイプラインとする。

---

# 16. 設計原則

「かくしーと」の座標処理では、以下を原則とする。

1. **PDF座標を唯一の正規座標系とする**
2. 永続化する座標はPDF座標のみとする
3. 画面座標は一時的な表示・入力情報として扱う
4. PDF → 画面変換は表示時に行う
5. 画面 → PDF変換はユーザー入力時に行う
6. ズーム・パン・画面サイズ変更によって保存データを変更しない
7. ページごとのPDFサイズを考慮する
8. 将来的な回転・ズーム・パン等に対応できるよう、変換処理を独立した機能として実装する

---

## 17. 全体イメージ

```text
                    ┌──────────────────┐
                    │   PDF座標系       │
                    │  Canonical       │
                    │  Coordinate      │
                    │  System          │
                    └────────┬─────────┘
                             │
                 ┌───────────┴───────────┐
                 │                       │
              保存                     表示
                 │                       │
                 ↓                       ↓
          Marker / Annotation      座標変換
                                         │
                              ┌──────────┴──────────┐
                              │                     │
                            Zoom                   Pan
                              │                     │
                              └──────────┬──────────┘
                                         ↓
                                  ┌──────────────┐
                                  │ 画面座標系   │
                                  └──────────────┘
                                         │
                                         ↓
                                  Canvas / Overlay
```

この設計により、**PDFそのものを変更せず、PDFの上に重ねた透明レイヤーへマーカーを描画する方式**と、座標管理をきれいに分離できる。
